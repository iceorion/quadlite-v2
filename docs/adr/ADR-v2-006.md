# ADR-v2-006：B4 列表视图规则层、状态内核与真实控件推迟

- **状态**：生效（2026-11-06）
- **批次**：B4（列表 / 七档视图 / 自然排序 / 分组 / 列头拖宽与筛选 / 显示开关 / 选择 / 命中 / 状态栏 / 快捷键）
- **关联**：`design-v2.md` §2.1 FR-09..17 / §5.9 / §5.10 / §7.1 / §8.1 / §8.2 / 附录 C；`ADR-v2-002` D5、`ADR-v2-004` D1/D6、`ADR-v2-005` D2/D6/D7

## 决策

### D1（沿用）规格一字不改，布局决策继续挂起
`design-v2.md` 保持 **v1.2**。B4 的 FR-09..17 与十个门卡组（`view-*` / `sort-*` / `group-*` / `cols-*` / `filter-*` / `toggle-*` / `select-*` / `hit-*` / `status-*` / `keys-*`）在 S3 就已在附录 C 与 §8.1 登记，`check-trace` 天然绿，本批**不需要新增需求、不需要改规格**。用户提出的自定义分割线拓扑仍在讨论中、未拍板，与 B4 无交集：B4 处理的是「一个窗格里显示什么、怎么选、怎么点」，布局处理的是「几个窗格、怎么摆」，两者替换边界不相交（见 `ADR-v2-005` D7）。

`check_list_specs.py` 增加一条「规格与实现一致」门卡：规格 §8.1 的 B4 门卡声明或 v1.2 状态被改动即判红。与 B3 的同名门卡并列，防止实现与规格静默漂移。

### D2（沿用 B1/B2/B3 的证据分层）B4 交付可验证内核，不冒充可运行应用
| 层 | 内容 | 验证方式 | 结论 |
|---|---|---|---|
| L0 规则层（Core） | B4 新增 11 个零 I/O 类型：视图补充规则、排序 / 分组、列宽偏好、四列筛选、显示开关、选择输入、目录分批、命中测试、状态栏、快捷键表 | CI 以 `/langversion:5` 编译并运行零依赖 C# runner（33 组） | 列表视图算法实测（CI 远端） |
| L4 状态内核（App） | `ListViewState` / `ListViewCommands`：只读 Core 结果，装配列表视图状态与快捷键派发 | CI 编成 library（只编译、不运行）+ `check_list_specs.py` 静态契约 | 结构与语法可判，运行期行为未验证 |
| 真实表现层 | WPF 列表控件 / 虚拟化面板 / 列头 UI / 拖放 / 图标与缩略图渲染 / 框选交互 / 系统原生右键菜单 / 冲突与进度面板 | B4 后续批次、B5、B6、B7、发布线 | **未实现 / 未验证** |

本机安全策略禁止执行系统 C# 编译器，故本机只跑 Python 静态门卡；不把静态绿写成算法跑通，也不把 CI 编译写成应用可用。

### D3（新增）B1 已有 L0 基础，B4 补的是规格里剩余的判据
B1 已交付列表视图的 L0 骨架：`ViewSpecs`（七档视图）、`ColumnLayout`（列宽恒等式）、`NaturalComparer`（自然排序）、`SelectionRules`（Ctrl+A 排除三类）、`RowEntry`。B4 **不重复定义、不改名**，只在其上补齐 §5.9 / §5.10 里尚未可判定的规则：

- `EnumBatchRules`：4096 / 批、可取消、`generation` 迟到批次丢弃、虚拟滚动只物化可见行（FR-09）。复用 `NavRules` 的同一迟到批次判据。
- `ViewRules` / `SortRules` / `GroupRules`：图标档不渲染组头、缩略图目标唯一来源、列头点击切换升降序、名称列走自然排序、组头不进显示行集、组内不二次排序（FR-10 / FR-11）。
- `ColumnPrefRules`：四条边界可拖、双击复位 `0=自动`、偏好按标签一份、几何宽度只从 `ColumnLayout.TryFor` 出（FR-12）。
- `FilterRules`：四列 / 大小五档 / 同列「或」跨列「与」、导航清 F5 留、不写会话、箭头按全量表、**状态栏 / Ctrl+A / 拖放源 / 操作源四来源一律读显示行集**（FR-13、§8.1 B4 特别判据）。
- `ToggleRules` / `SelectionInput` / `HitTestRules` / `StatusRules` / `KeyMap`：四开关 16 组合与三态过滤、不回顶、缩略图开关不重枚举；点选 / Ctrl / Shift 多选、框选仅图标档、详细信息档框选列为非目标；四类命中单一来源、双击 / 拖入 / 右键共用；状态栏按筛后行计数且文案来自结构化结果（不得由「没有异常」推出成功）；13 键快捷键表逐键给出作用域与忙时行为（FR-14..17、§5.10）。

### D4（新增）门卡与负向对照
C# runner 由 27 组扩到 **33 组**：新增 `group-*` / `filter-*` / `toggle-*` / `hit-*` / `status-*` / `keys-*` 六组；并为既有 `view-*` / `sort-*` / `cols-*` / `select-*` / `enum-*` 五组追加 B4 规格断言。`check_core_specs.py` 的 Core 类型 32 → 43、门卡组 27 → 33、枚举 25 → 36。

新增 `tools/check_list_specs.py`（B4 独立静态契约门卡）：B4 Core 类型齐备 / App 状态内核齐备 / 门卡组注册 / 规格关键常量与不变量（4096 / 四列 / 五档 / 13 键 / 组头不进行集 / 筛选不写会话 / 开关写会话）/ 规格与实现一致 / App 零 I/O / C# 5 语法。`run_tests.py` 由 32 组扩到 **39 组 / 31 条负向对照**，新增 1 组 `check-list-specs` 正向与 6 类 B4 负向对照（删筛选类型 / 删 B4 门卡组 / 批次常量漂移 / 删 App 状态内核 / App 层注入 `System.IO` / 注入 C# 6 语法），逐条实测变红。

### D5（新增）CI 一步
`check-list-specs`（B4 静态契约）。`csharp-runner` 与 `csharp-app-compile` 都用目录 glob 自动包含 B4 新增的 11 个 Core 文件与 2 个 App 文件，无需新增编译步骤：`csharp-runner` 编译运行 33 组，`csharp-app-compile` 把 Core + App（现 4 个 .cs）编成 library，只编译不运行、不引用呈现框架程序集。

### D6（偏差，如实登记）§8.1 B4 未交付完的部分
- **真实 WPF 列表控件 / 虚拟化面板 / 列头拖宽与筛选面板 / 框选交互 / 拖放 / 图标与缩略图渲染**未实现；`src/QuadLite.App/` 里只有纯逻辑状态类型，不能启动、不能交互。
- 「4096 条 / 批」只落地纯函数判据；`DirSource`（B2）当前批次大小为 128，真实 `FindFirstFileExW` + `LARGE_FETCH` 枚举未接入，两者不一致属 B2 遗留偏差，本批不改 Fs 层、不冒充已对齐。
- 「名称按拼音分桶 / 修改日期月历 / 类型动态枚举」只落地桶键组合逻辑，真实拼音映射与动态类型枚举未接入。
- 「选中集 / 状态栏 / 拖放源 / 操作源读显示行集」只落地一致性判据，真实 UI 消费方未接入。
- 系统原生右键菜单属 B5，图标与缩略图属 B6，冲突 / 进度 UI、真实 `IFileOperation` 搬运、系统剪贴板互通、watcher 运行期仍属 B2/B3 偏差，未实现 / 未验证。
- **本批不等于「应用可启动」**。§8.4「每批结束应用必须可启动」仍按 `ADR-v2-002` 的证据分层记为未达成，不宣称 MVP 可交付。

### D7（影响面）布局决策若改，B4 不需返工
若用户将来拍板采用自定义二叉分割树，替换边界仍是 `ADR-v2-005` D7 划定的 `LayoutMath` / `SplitMath` / `PaneSet` / `ShellState`；B4 的十一个规则类型只关心单窗格内的行集、排序、筛选、选择、命中、状态与快捷键，**不受窗格数量与落位模型影响**。本批不预判结论，也不提前改规格。

## 理由

1. 用户「继续 B4」，原计划即 `design-v2.md` §8.1 的 B4 定义；布局新方案尚在讨论，写进代码或规格都会替用户拍板。
2. B4 门卡全部是纯逻辑判据（分桶组合、跨列与、四来源一致、快捷键表），可以在零 I/O 条件下 100% 单测；把不可在本机验证的 WPF 控件混进来只会稀释证据，与 B0–B3 的纪律一致。
3. B1 已有 L0 基础，B4 在其上补齐规格判据而不是另起一套，保持「已验证行为契约沿用」的 DD-07。
4. 把「规格与实现一致」做成门卡，是对上一轮越界的制度性兜底延续，而不是一次性道歉。
