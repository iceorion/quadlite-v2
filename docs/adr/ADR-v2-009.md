## 决策

### D1（沿用）布局保持 v1.2 四档，规格一字不改

用户对本批的指令是「继续 B7」。沿用 `ADR-v2-008` D1 的拍板：1/2/3/4 四档布局不变，自定义二叉分割树方案不采纳，`design-v2.md` 仍为 **v1.2**，FR-01 / §5.8 / §8.1 / 附录 C 未改。B7 属系统工程域，与窗格数量、落位模型无交集，`ADR-v2-005` D7 的替换边界不触发。新增的 `check_selftest_specs.py` 第 10 项继续核对规格版本与 B7 判据声明，不因已拍板而放松。

### D2（沿用 B1–B6 的证据分层）B7 交付可判定内核，不冒充产品 exe

| 层 | 内容 | 验证方式 | 结论 |
|---|---|---|---|
| L0 规则层（Core） | 新增 9 个零 I/O 类型：命令行契约 / 自测报告 / 门卡总表 / 账本 / BUILD.txt / 出包自检 / 预算表 / 崩溃摘要 / 单实例 | CI 以 `/langversion:5` 编译并运行零依赖 C# runner（61 组） | 规则算法实测（CI 远端） |
| L4 状态内核（App） | `SelftestState`（报告明细行、行数、verdict、退出码）/ `PackageState`（BUILD.txt 七字段、包自检） | CI 编成 library（只编译）；B7 起 runner 编译同时包含 App 文件，故状态内核也被实跑断言 | 结构与语法可判，运行期 I/O 未验证 |
| 真实产品形态 | 产品 exe 的 `--selftest`、`BUILD.txt` 真实采集、单文件出包、`--bench` 采样、崩溃日志写入、零写入三段取证 | 发布线 H1–H6 / 出包批次 | **未实现 / 未验证** |

本机按既定纪律不执行系统 C# 编译器，只跑 Python 静态门卡；不把静态绿写成算法跑通，也不把 runner exe 的报告写成产品 exe 已能自测。

### D3（修订 B2）补齐 §6.4 命令行契约，修掉既有漂移

B2 的 `CliArgs.Parse` 只接受 `--selftest` / `--shot --split` / `--diagnose` / `--shell-menu-host` 四个参数，而 §6.4 主表列了九项（`--bench` / `--open-test` / `--thumbs` / `--dumpmenu` / `--data-dir` / `--no-persist` 等），且 §5.13 明确 `--shot` 不参与单实例，B2 却只对 `Diagnose` / `SelfTest` 豁免。这是「门卡验证规格声明、未覆盖实现」的一处真实漂移。

本批新增 `CliContractRules`（主表 9 项 + `--shot` 三个修饰项 + B2 兼容两项 = 14 个已知参数），并让 `CliArgs` **真正复用**它：

- `Parse` 用 `IsKnown` 判合法参数，按 `RequiresValue` / `AllowsOptionalValue` / `IsShotModifier` 消费取值；`--shot` 的值可选，因此 B2 的 `--shot --split <payload>` 与 §6.4 的 `--shot <path>` 同时合法；
- `LegalParameters()` 委托契约表，不再另写一份纸面清单；
- `ParticipatesInSingleInstance` 委托 `SingleInstanceRules`，改为只有 `CliMode.Normal` 参与单实例，补齐 `--shot` / `--shell-menu-host` 的诊断豁免。

B2 的 `cli-*` runner 断言（空参数、selftest、diagnose、shot+split、split 缺 shot、未知参数拒绝、合法参数列表）**一条未删、语义未改**，全部保留；B7 另加 `cli-contract` / `cli-diagnostic-modes` 两组断言覆盖新参数与豁免行为。`check_selftest_specs.py` 第 7 项静态核对三处委托，防止契约表与实际解析再次分叉。

### D4（`--selftest` 报告形态落地为可实跑输出，不是只断言常量）

§8.1 B7 判据要求 `--selftest` 输出带 `verdict:` 且 **≥100 行**。B7 让 runner exe 真实输出：门卡总表 50 行 + 预算表 4 行（只报数、`unmeasured` / 未验证）+ 账本 / 包自检 / BUILD 摘要 3 行 + 61 组结果行 + 尾部 2 行 = **120 行**，末行 `verdict:`，退出码 = 红条数。`SelftestReportRules.MinOutputLines = 100`、`SelftestState.MeetsMinimumLines()` 与 runner 的实际打印行数三方一致，并由 `check_selftest_specs.py` 第 6 项静态核对组数、明细打印与末行委托。

因此 CI 的 `csharp-runner` 编译命令自 B7 起同时包含 `src/QuadLite.App/*.cs`（此前只编 Core + Tests），`csharp-app-compile` 仍单独把 App 编成 library（最小文件数 8 → 10）。

### D5（门卡总表逐项一致，不做常量自证）

`GateInventoryRules.Gates()` 是 §7.1 第二列 50 个门卡 token 的可判定副本。`check_selftest_specs.py` 第 5 项**解析 §7.1 原文逐项比对集合**（不是只比一个数字），源码多一项、少一项或改名都会判红；负向对照 `gate-inventory-drift` 实测删掉 `menu-sentinel` 即变红。`check-trace` 仍以规格文档为唯一权威，本副本只供报告明细行与静态核对，不反向成为规格来源。

### D6（偏差登记）M2 判据仍未达成

§8.4 定义 M2 = B6–B7，判据是「图标与缩略图、自测装置、账本、单文件出包自检」。B7 交付的是自测 / 出包的**规则层与 runner 报告形态**，真实产品 exe 尚不存在，`BUILD.txt` 未生成，单文件出包未执行，图标缩略图未渲染。因此本批「完成」仍指批次规格内的可判定内核 + 门卡闭环，不等于 M2 可交付。此偏差与 `ADR-v2-005` / `ADR-v2-007` / `ADR-v2-008` 登记的同类偏差一致，规格未改。

## 理由

1. 用户明确「继续 B7」，且上一批已确认保持四档、规格不改；本批不引入布局返工。
2. B7 的三条判据（≥100 行报告 / BUILD.txt 字段齐 / 毫秒只报数）都可在零 I/O 条件下判定；把无法本机验证的真实出包混进来会稀释证据链。
3. D3 的漂移若不修，`--selftest` 的合法参数清单会继续是一张纸面契约；B7 正是修它的最后时点，且 B2 断言可完全保留，成本可控。
4. 把门卡总表做成「与规格原文逐项比对」，是对本仓最容易退化的「常量自证」式门卡的一次针对性补强。
5. 报告明细行标 `unmeasured` / 未验证，符合 §7.3 与 NFR-09：毫秒 / 时序只报数、不判定，不进 CI 闸门。
