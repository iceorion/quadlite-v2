# ADR-v2-013：R3 浏览 / 搬运 UI 真实接线

- **状态**：生效（2026-11-15）
- **批次**：R3（规格外实现批次，`design-v2.md` v1.2 一字未改、四档布局不变）
- **关联**：`design-v2.md` §5.1 / §5.8 / §5.9 / §5.10 / §5.12 / §6.1 / §7.1 / §8.1；`ADR-v2-003`、`ADR-v2-004`、`ADR-v2-011` D2、`ADR-v2-012` D3/D4/D6；`docs/negative-controls.md`、`docs/run-ledger.md`

## 背景

R1 交出可编译、可自测的真实单文件 WPF exe，但窗口只把四档槽位当文字展示；R2 把 `IShellTransport` 的真实实现编进 exe，却仍默认关闭、没有任何用户可触发的入口。`ADR-v2-012` D6 如实记录「产品能力仍为零：没有浏览 / 搬运 UI，transport 默认关闭，用户无法触发真实操作」。

`ADR-v2-011` D2 与 README 原本把 R3 写成「接原生菜单宿主、图标渲染与浏览 / 搬运 UI」。本批把范围收敛，理由见 D1。

## 决策

### D1（新增）R3 范围收敛：先接浏览 / 搬运链路，菜单与图标另立批次

R3 只做 **浏览 / 搬运 UI 真实接线**，把 R2 的 transport 挂到用户可触发的操作上：

- 四档布局由 `LayoutMath.Slots` 真实落位到 3×3 `Grid`（不再只是打印槽位文字）。
- 四个 `PaneView` 用 `IDirSource`（`QuadLite.Fs.DirSource`）真实枚举目录，后台 worker + `Dispatcher` 回 UI 线程，切目录 `generation` 前进并**在 worker 与 UI 两侧各判一次**迟到批次。
- 真实 WPF `ListBox` 呈现条目，双击导航、地址栏走 `AddressRules.TryParse`，选中集与状态栏计数走 `Selection` / `StatusRules`。
- 工具栏「复制 / 移动 / 删除」经 `OpRequest`（不可变快照）→ `OperationCoordinator` → `ShellFileOperator` → `ShellTransport` 调用 R2 的真实链路；状态文案只从结构化结果经 `StatusRules.ResultText` 产出。

**范围收敛理由**：原生菜单宿主需要第二套 COM 声明（`IContextMenu` / `IContextMenu2/3`）与 owner 窗口消息转发，图标缩略图渲染需要第三套（WIC / `IShellItemImageFactory`）；两者都会再改 `tools/com_policy.py` 的白名单，与浏览链路正交。一次做三套会让 CI 编译失败难以定位，也违反 B0–B8 以来「一批一个功能域」的纪律。因此：

| 批次 | 范围 |
|---|---|
| **R3（本批）** | 四档落位 / 目录枚举 / 列表控件 / 状态栏 / 搬运命令接线 |
| **R4** | 系统原生菜单 COM 宿主（§5.2 标准四步 + `IContextMenu2/3` 消息转发） |
| **R5** | 图标与缩略图渲染（四级通道 / WIC 白名单 / LRU / 唯一写入例外） |

规格 §8.1 批次表不写入 R 系列，本表只是仓库内的实现顺序登记。

### D2（新增）Host 层四个注入端口，全部零 I/O

`src/QuadLite.Host/HostPolicies.cs` 提供 `HostClock` / `HostDangerPolicy` / `HostPreflight` / `HostRefreshSink`，让 `OperationCoordinator` 能在不碰文件系统、注册表、网络、配置目录的前提下工作。判级端口对 `PermanentDelete` 一律返回 `Reject`，其余返回 `Confirm`；预检端口如实返回「无冲突且无错误」的内存结论，不冒充真实盘符 / 只读探测。

`UiContractRules` 是同文件内的零 I/O 纯函数判据（四档槽位表、窗格对象持久、迟到批次、transport 诚实文案、无推断成功、状态栏三段、`IsRuntimeVerified() == false`），供产品 `--selftest` 直接复用，不创建窗口、不实例化 COM。

### D3（沿用并强化）transport 默认关闭，绝不冒充成功

沿用 `ADR-v2-012` D3/D4：`ShellTransport` 默认 `Enabled = false`，R3 **不提供任何 UI 启用入口**。`BrowseCommands.Execute` 在关闭时直接返回「搬运未执行：…（未启用 / 未验证）」；启用后也只在 `result.Accepted && result.Record != null && result.Error == ErrorClass.None` 时才输出「搬运完成」，其余一律「未执行 / 未成功」。`MainWindow` 状态栏常驻 `disabled by default / 未验证`，并逐项列出未实现能力。

这条纪律对应 §5.12 与 `StatusRules.RejectsInferredSuccess()`：**「没有异常」不构成成功**，也不把「没有报错」写成真机取证。

### D4（新增）门卡、负向对照与 CI

新增 `tools/check_ui_specs.py`（交付物 / 真实列表控件 / `IDirSource` 与迟到批次 / 四档真实落位 / 搬运接线 / 默认关闭且不冒充成功 / R2 分层 COM 口径未被破坏 / Host 分层纪律与 C# 5 / 单程序集一致性 / CI 与旧闸门 / 规格 v1.2 未改 / 证据文档 / 产品 selftest / 诚实标注，共 12 组静态判据）。`run_tests.py` 新增该门卡的正样本与 R3 负向对照；CI 新增 `check-ui-specs` 一步；`build.ps1` 四层源码计数由 100 更新为 103；`SelftestRunner.cs` 增 R3 运行时契约断言。

`check_realization_specs.py` / `check_transport_specs.py` 的 N/A 措辞同步 R3 现状（「窗口仍无浏览 / 搬运 UI」→「已接线但运行期未验证」），**不改它们的判据与既有负向对照**。

### D5（如实登记）M1 / M2 / M3 仍不成立

R3 把「可编译、可静态判定的浏览与搬运链路」接入证据闭环，但真实键鼠交互、真实目录内容、拖放、系统原生菜单 COM 宿主、图标与缩略图渲染、七档视图与筛选、会话与书签、`run.lock` 与 `WM_COPYDATA` 转发、`--shot` / `--bench` 诊断装置、真实 `IFileOperation` 运行期行为全部未实现或未验证。CI 只编译单 exe 并跑无窗口 `--selftest`，**不开窗口、不枚举目录、不实例化 COM**。`ReleaseState.IsPublishable() == false`，**M1 / M2 / M3 均不成立，没有可下载版本**。

## 偏差登记（未实现 / 未验证）

- **§5.2「成熟绑定」偏差仍在**：R2 的 SDK 逐字对应托管声明未替换；R3 不新增 COM 声明，也不修这个偏差。
- **真实交互未验证**：WPF 窗口未在本机或 CI 打开；键鼠、双击导航、地址栏、工具栏按钮、异步枚举与 `Dispatcher` 排队时序、四档切换的实际渲染全部未取证。
- **真实 shell 搬运未验证**：transport 默认关闭，CI 不调用 `PerformOperations`；R2 偏差登记的所有运行期风险继续有效。
- **UI 能力仍有缺口**：拖放、原生菜单宿主、图标缩略图渲染、七档视图、列头筛选、显示开关、分组、快捷键、单实例后两段、崩溃哨兵、`data\` 配置读写、MSBuild 出包路径、H1–H6 / C4 取证全部未实现或未验证。
- **端口实现是最小内存版**：判级 / 预检为占位策略，不代表 §5.12 的完整危险判级矩阵。

## 证据与结论

- 本机：十五个 Python 门卡 / 自测脚本（14 个 `check_*.py` + `run_tests.py`）逐项实测绿，`run_tests.py` 118 组 / 0 失败、103 条负向对照逐条变红（含 15 条 R3），见 `docs/run-ledger.md` R3 行；功能提交 `head_sha = 8fb78aa`。
- CI：**首次实跑已通过**，run `43717485240`（push head `0836109`：功能提交 `8fb78aa` → 账本回填 `d8ba545` → 编译修复 `0836109` → 本次 CI 结论回填，沿用 B6–B8 / R1 / R2 三段式）。job `gates` 结论 `success`，二十个门卡 / 编译步骤逐项 `success`：`check-ui-specs` `success`；`csharp-fs-compile` / `csharp-app-compile` `success`；`real-exe-build` `success` ⇒ 四层 103 个 .cs 一次编成单 exe、`BUILD.txt` 七字段齐；`real-exe-selftest` `success` ⇒ 产品 `--selftest` 报告 ≥100 行、末行 `verdict: GREEN`、退出码 0（含 6 组 R3 契约断言）。
- **首次判红如实登记**：功能提交 `d8ba545` 的 run `43716871530` 在 `real-exe-build` 判红（`real-exe-selftest` 跳过），根因是 `SelftestRunner.cs` 把三个 `out` 变量放在 `&&` 短路链后直接使用，触发 C# 5 的 CS0165 definite-assignment 错误；Python 门卡与 Fs / App 库编译均 `success`，因为它们不编 Host 层。修复提交 `0836109` 显式初始化 `dir` / `file` / `dest`（并给 `PaneView.GoUp` / `MainWindow.GoToAddress` 的 `out` 变量加初始化），同时让 CI `real-exe-build` 把 `error CS` 行以 annotation 暴露，避免后续盲猜。**该次红不作为通过证据**。日志端点匿名 403，按步骤 `success` ⇒ 退出码 0 记录，不读日志原文、不推断。
- 结论：**R3 让窗口第一次具备「可浏览目录、可发起搬运请求」的代码路径**，但 transport 默认关闭、真实交互与 shell 运行期全部未验证，**不等于 MVP，也不等于可发布版本**。
