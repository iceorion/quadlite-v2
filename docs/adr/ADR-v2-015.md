# ADR-v2-015：R5 图标 / 缩略图取图链路与呈现接线

- **状态**：生效（2026-11-18）
- **批次**：R5（规格外实现批次，`design-v2.md` v1.2 一字未改、1/2/3/4 四档布局不变）
- **关联**：`design-v2.md` §5.11 / §5.12 / §5.13 / §2.2 NFR-02 / §7.1 `icon-*` `thumb-*` `thumb-nowrite`；`ADR-v2-008`（B6）、`ADR-v2-012`（R2 成熟绑定偏差）、`ADR-v2-013` D1（R4/R5 拆分）、`ADR-v2-014`；`docs/negative-controls.md`、`docs/run-ledger.md`

## 背景

B6 只交付了图标 / 缩略图的零 I/O 规则层：Core 的 `IconChannelRules` / `ThumbWhitelistRules` / `ExifOrientationRules` / `ThumbQueueRules` / `ThumbCacheRules` / `VideoThumbRules` / `ThumbToggleRules` / `ThumbWriteRules` 八个类型，加 App 的 `ThumbState` / `ThumbCommands`。真实 WIC 解码、系统图像工厂、后台 worker、LRU 介质与三段取证从未接入（ADR-008 D6）。

ADR-013 D1 把 R3 之后的实现拆成 R4（原生菜单 COM 宿主）与 R5（图标与缩略图渲染），理由是两者各需一套正交的 COM 绑定，「一批一个功能域」。R4 已按 ADR-014 落地并默认关闭。R5 是既定 R 系列的最后一批，仍不改规格。

## 决策

### D1（新增）R5 范围：取图链路 + 列表项呈现接线，其余功能域不动

- Fs 层新增 `src/QuadLite.Fs/IconThumbHost.cs`：`IShellItemImageFactory` 真实绑定、独立 STA 后台 worker、`try-finally` 释放、默认关闭。
- `ShellComInterop.cs` 扩为三套 COM 声明共用的唯一白名单，第三套只加一个接口。
- Host 层新增 `src/QuadLite.Host/IconThumbCommands.cs`：复用 App `ThumbCommands.Request` 做零 I/O 派发、装配不可变 `IconThumbRequest` 快照、HBITMAP → `BitmapSource`、WPF 内置 WIC 包装做两档自解码与 EXIF 方向。
- `PaneView` 列表项模板带图标位、后台取图、`generation` 二次校验；`MainWindow` 注入 provider 并在状态栏明示默认关闭。
- 新增 `tools/check_icon_thumb_specs.py`、`ADR-015`、负向对照登记、CI 一步、产品 `--selftest` 八组 R5 断言。

拖放、七档视图与筛选、会话与书签、`run.lock` / `WM_COPYDATA`、`--shot` / `--bench`、L3 菜单崩溃哨兵与自绘兜底、H1–H6 / C4 取证均不在本批。

### D2（新增，明确偏差）第三套 COM 声明收敛为 `IShellItemImageFactory` 一槽

ADR-013 D1 预期 R5 需要「WIC / `IShellItemImageFactory`」两套手写 COM 声明。实测后收敛：

| 能力 | 本批做法 | 理由 |
|---|---|---|
| 图标 / 视频缩略图取图 | `IShellItemImageFactory` 托管声明（唯一新增 COM 接口） | §5.11 明确视频走系统图像工厂；四级图标通道也可由 `SIIGBF_ICONONLY` / `SIIGBF_THUMBNAILONLY` 取 |
| 图片两档自解码 | WPF 内置 `BitmapDecoder` / `TransformedBitmap`（系统 WIC 托管包装） | 零 NuGet、零第三方解码器，不需要手写 `IWICImagingFactory` 等二十余槽位的 vtable |

这是对 ADR-013 D1 预期的**明确收敛**，也是 §5.2「成熟绑定」偏差的部分消解：图片路径不再手写 COM vtable。偏差本身不撤销——`IShellItemImageFactory` 仍是 SDK 逐字对应的托管声明（ADR-012 口径继续有效）。

权威值取自本机 Windows SDK 10.0.19041.0 的 `um/ShObjIdl_core.h`：

| 接口 / 常量 | 值 | 出处 |
|---|---|---|
| `IID_IShellItemImageFactory` | `bcc18b79-ba16-442f-80c4-8a59c30c463b` | 8693 行 `MIDL_INTERFACE` |
| vtable | IUnknown 之后仅 `GetImage(SIZE, SIIGBF, HBITMAP*)` 一槽 | 8697–8700 行 |
| `SIIGBF_*` | `RESIZETOFIT 0` … `SCALEUP 0x100` 共十个值 | 8663–8675 行 `enum _SIIGBF` |

`SIZE` 用两个 `int`（LONG cx/cy）按值传入；`SHCreateItemFromParsingName` 以新 `EntryPoint` 重载输出图像工厂；HBITMAP 由 `gdi32!DeleteObject` 释放。`tools/com_policy.py` 的 `EXPECTED_IDS` / `EXPECTED_METHODS` 扩到 R5 一段，`check-transport-specs` 与 `check-icon-thumb-specs` 都遍历全表硬校验，不另立口径。

### D3（沿用 B6）四级通道与盘符真实路径

`IconChannelRules` 是唯一来源：16 / 48 / 96 / 256 四档、exe 两段式（先扩展名通用图再真实路径回填）、jumbo 透明画布回落 48、盘符逐档按真实路径取图且不得与通用文件夹图标逐像素相同。`IconThumbHost` 用 `IconChannelRules.IsKnown` 硬校验请求尺寸，非法档直接拒绝，不悄悄换算；`IconThumbCommands.Provide` 用 `IconChannelRules.ForView` 取当前视图档。真实逐像素比对属 H1–H6 取证，未验证。

### D4（沿用 B6）调度、缓存与开关

- 单 worker、可见优先：`ThumbQueueRules.WorkerCount == 1`，`PaneView.QueueIcon` 在后台线程取图，不占 UI 线程；`BitmapSource` 跨线程前先 `Freeze()`。
- 迟到结果丢弃：回 UI 时用 `ThumbQueueRules.ShouldApplyResult(generation, state.Generation, false)` 二次校验，与 R3 的枚举批次同一判据。
- LRU 双闸：96 MB + 1500 条，缓存键四段且 `i|` / `v|` 类型隔离（`ThumbCacheRules.Key` / `PrefixOf`）；`Failed` 进负缓存不重试，回落类型图标。
- EXIF 八值方向参与渲染变换（`QuarterTurns` / `FlipHorizontal`），按 B6 口径**不改变**缓存键（`ChangesCacheKey() == false`）。
- 缩略图开关切换不重枚举、不新建 job、复用缓存（`ThumbToggleRules`）。
- 真实 LRU 介质、淘汰时机与队列实现仍未接入，全部「未验证」。

### D5（沿用 B6）视频容器、看门狗与唯一写入例外

15 种容器走系统图像工厂（`VideoThumbRules`），`IconThumbHost` 用 `TimeoutSeconds * 1000` 作为 `Thread.Join` 预算，超时即丢弃结果并把 worker 留作后台线程，不挂住进程；缺图 / 非图像分 `Missing` / `NotImage` 负缓存且不重试。写系统缩略图缓存是**唯一显式写入例外**，只在 `ThumbWriteRules.WriteAllowed(WriteZone.SystemCache, sameMotiveAsExplorer)` 为真时才允许；`data\` 之外零写入、禁止静默回落用户目录。「注册表 / 应用目录 / 系统缓存」三段取证属 H3，未执行，故本批**不宣称零写入已取证**。

### D6（新增，明确偏差）宿主默认关闭

`IconThumbHost.Enabled` 默认 `false`，Host 层不提供启用入口；`Provide` 在未启用时直接返回 `null`——图片两档自解码走 WPF WIC 包装读文件，同样属于真实 I/O，一并纳入该开关、不得绕过；列表项保持文字占位，状态栏写 `icon-thumb=wired but disabled by default / 未验证`。`check-icon-thumb-specs` 的 Host 判据与一条专门负向对照（`provider-bypasses-toggle`）守住这条分支。

规格 §5.11 的默认路径是「按视图档渲染图标 / 缩略图」，因此这是**明确偏差**，理由与 R4 D5 一致：L3 崩溃哨兵、自绘兜底、HBITMAP / thumbcache 生命周期的真机取证、H1–H6 与 C4 均未完成，默认启用会把第三方 shell 扩展 / 解码器异常直接带给主进程。R2 / R3 / R4 的默认关闭纪律在 R5 继续沿用，不因「最后一批」而放宽。

### D7（新增）分层与构建纪律

- Core 零 I/O；Fs 适配器与真实 COM；App 状态内核零 I/O；Host 真实呈现。Host 不写 `using System.IO`、不写 COM 声明、不手写 vtable、不自行启用宿主。
- **分层收敛需登记**：Host 的 `DecodeImage` 通过 `new Uri(path)` 使用 WPF 内置 WIC 包装读文件，未走 Fs 端口。这是为避免手写 WIC vtable 的取舍，门卡按字面判定 Host 零 `System.IO`，但真实 I/O 归属的偏差写在本条，不冒充「全部 I/O 都经 Fs」。
- `build.ps1` 源码计数 105 → 107（Core 78 + Fs 9 + App 12 + Host 8），保留 UTF-8 BOM（Windows PowerShell 5.1）；`QuadLite.Host.csproj` 纳入 `IconThumbCommands.cs`；CI 新增 `check-icon-thumb-specs`；`check_open_source.py` 继续排除 `dist/` / `bin/` / `obj/` / `data/`。
- `docs/negative-controls.md` 的「写入例外清单」保持恰好一条 thumbcache，B6 的 `check-icon-specs` 与 R5 门卡同时校验。

### D8（沿用）证据链与 CI 口径

三段式提交（功能 / 账本 `head_sha` 回填 / CI 结论回填）不变；本机只跑 Python 门卡，不执行 C# 编译器；CI 的 `real-exe-build` 与 `real-exe-selftest` 实跑四层单 exe 编译与无窗口 `--selftest`。CI 不开窗口、不枚举目录、不实例化 COM、不解码、不写 thumbcache，结论按 jobs API 的 step `conclusion` 记录，日志端点匿名 403 时不读原文。

## 证据与结论

- 本机：16 个 `tools/check_*.py` 逐个 `rc=0`，`run_tests.py` 162 组 / 0 失败（145 条负向逐条变红，含 23 条 R5），`design-v2.md` diff 为空，`build.ps1` BOM 保留，四层 107 个 `.cs`。本机**不执行** C# 编译器。
- CI：**结论待回填**。功能提交 → 账本 `head_sha` 回填 → push 后的 `gates` job 按步骤 `success` 回填 `docs/run-ledger.md` R5 行与本文件；`real-exe-build` 编译四层 107 个 `.cs`，`real-exe-selftest` 跑产品 `--selftest`（≥100 行 / `verdict: GREEN` / 退出码 0 / 8 组 R5 断言）。
- 未验证：真实 `IShellItemImageFactory` 调用、HBITMAP 逐像素比对、WIC 解码介质、图标呈现、thumbcache 写入、三段取证、看门狗真实中断、H1–H6 / C4、真实键鼠交互与 shell 运行期。
- `ReleaseState.IsPublishable() == false`，**M1 / M2 / M3 均不成立，没有发布版本**。

## 澄清与作废

- **作废**：ADR-013 D1 中「R5 需要 WIC + `IShellItemImageFactory` 两套手写 COM 声明」的预期（改按 D2 收敛）；ADR-014 D1 / README 中「图标缩略图渲染仍未接入」的时点结论（R5 起已接线但默认关闭）。
- **不作废**：B6 的规则层与全部常量；R2 / R3 / R4 的默认关闭纪律；§5.2「成熟绑定」偏差（ADR-012）；规格 v1.2 与四档布局。
