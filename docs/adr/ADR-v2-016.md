# ADR-v2-016：R6 真机证据批次（阶段 0 COM 探针 + 阶段 1 transport 试点）

- **状态**：生效（2026-11-18）
- **批次**：R6（规格外实现批次，`design-v2.md` v1.2 一字未改、1/2/3/4 四档布局不变）
- **关联**：`design-v2.md` §6.4（诊断参数）/ §5.1（IFileOperation）/ §9（证据等级）；`ADR-v2-011`（R1 产品 exe）/ `ADR-v2-012`（R2 transport）/ `ADR-v2-013`（R3 UI 接线）；`docs/run-ledger.md`、`docs/negative-controls.md`

## 背景

B0–B8 建立规则层，R1–R5 把真实宿主、IFileOperation transport、浏览 / 搬运 UI、原生菜单宿主、图标缩略图宿主逐批接进单一产品 exe，CI 每批都编译并跑无窗口 `--selftest`。但 CI 从未打开窗口、枚举目录、实例化 COM、执行搬运：所谓「接线完成」只等价于「代码存在且能编译」，三个宿主 `Enabled` 默认 `false` 且 Host 层没有启用入口。规格 §5.2 / §5.11 的默认路径与本实现的偏差登记在 ADR-014 / ADR-015，启用时机被推迟到崩溃哨兵与 H1–H6 取证之后。

本批解决的问题是：**在不改规格、不动 Normal 路径默认关闭纪律、不破坏任何既有门卡的前提下，提供一条受控的真机取证通道**，先把「COM 能否实例化」「IFileOperation 真机能否完成一次搬运」两个基础事实拿到手。

## 决策

### D1（新增）诊断入口复用 `--diagnose`，不新增 CLI 参数、不改契约表

§6.4 的九个主参数与 B2 兼容参数合计 14 项由 `CliContractRules.ParameterCount == 14` 固定，`check_core_specs` 与 `run_tests` 负向对照都依赖它。新增参数会连带改契约表、门卡与负向对照，违反「一次一个功能域」。因此复用已存在的 `CliMode.Diagnose`（`--diagnose`，B2 起即为合法 flag）作为受控入口。Normal 路径不变：`Program.cs` 只在 `CliMode.Diagnose` 分支调用探针，其余诊断模式（Shot / ShellMenuHost）仍返回「未实现 / 未验证」，`check_realization_specs` 的 `diagnostic modes honest` 判据继续命中。

### D2（新增）阶段 0：COM 实例化探针，只判「能否实例化」

Fs 层新增 `ShellComProbe.cs`：独立 STA 内 `CoInitializeEx` → `Activator.CreateInstance(Type.GetTypeFromCLSID(CLSID_FileOperation))` → `Marshal.ReleaseComObject` → `CoUninitialize`，输出 `coinit-hr / instantiated / release-failed / detail / clsid`。**不碰任何文件、不调用 `PerformOperations`、不开窗口**。CLSID 复用唯一白名单 `ShellComInterop.cs` 的 `ShellIds`，本文件是 COM 调用点、不是声明点，`com_policy` 分层口径不变。

### D3（新增）阶段 1：transport 真机试点，限定在系统 temp 的自建目录

Fs 层新增 `ShellTransportProbe.cs`：在 `Path.GetTempPath()` 下建带唯一前缀的子目录，写入一个测试文件，显式 `Enable()` 一个全新 `ShellTransport`，依次跑 Copy / Move / Recycle 三种 `OpKind`，每种输出 `error / callbacks / items / 目标存在性` 等结构化字段，结束即删目录。**不碰用户文件**；不做函数指针、不手写 vtable、不引入 COM 声明；输出只写结论字段，不写日志原文或崩溃路径（§10 / SECURITY.md）。

### D4（新增）CI 新增 record-only 探针步骤与 artifact 上传

`ci.yml` 在 `real-exe-selftest` 后新增两步：
- `real-exe-probe-com`：以 `--diagnose` 跑阶段 0+1 探针，stdout 落盘为 `PROBE-COM.txt` 并打进日志。**无论探针结论如何都 exit 0**——COM 在 Session 0 里实例化失败本身就是有价值的证据，不应当作构建失败。
- `upload-artifact`：上传 `QuadLite.exe` + `BUILD.txt` + `PROBE-COM.txt`，供本机交互桌面做后续人工 / 真机验证。

### D5（沿用）分层、默认关闭与诚实标注

- Host 层零 `System.IO` / 零 COM 声明 / 零 verb：`check_ui_specs` 的 `HOST_FORBIDDEN` 继续绿；探针全部落在 Fs 层。
- 三个宿主仍默认关闭、Host 层仍无启用入口：`check_transport_specs` / `check_menu_host_specs` / `check_icon_thumb_specs` 的默认关闭判据未动。
- `design-v2.md` 一字未改（v1.2）：所有门卡的「规格仍 v1.2」判据未动。
- 本批**不宣称**任何运行期结论，也不改变 `ReleaseState.IsPublishable() == false` 与 M1 / M2 / M3 不成立的现状。

## 证据与结论

- 本机静态：16 个 `tools/check_*.py` 逐个 `rc=0`、`verdict: GREEN`；`run_tests.py` 162 组 / 0 失败（145 条负向逐条变红）；源码四层 109 个 `.cs`（Core 78 + Fs 11 + App 12 + Host 8），`design-v2.md` diff 为空。
- 本机真实编译（回填）：用户在 WorkBuddy 安全中心放行 `csc.exe` 后，本机 `build.ps1` 实跑成功，`QuadLite.exe` 159232 字节、`sha256=495C35E1…E154`、`worktree=clean`、`package-selfcheck=PASS`，`BUILD.txt` 已采集。这取代了早先「本机不执行 C# 编译器」的口径——两个新 .cs 已在本机真实编译通过。
- 本机交互桌面真机实测（`--diagnose`，回填）：
  - 阶段 0：`coinit-hr=1`（RPC_E_CHANGED_MODE，STA 已初始化，属正常）、`instantiated=true`、`release-failed=false`、`detail=ok`、`clsid=3ad05575…8e09`——**IFileOperation 在本机真实实例化成功**。
  - 阶段 1：`copy / move / recycle` 三项均 `error=None callbacks=1 items=1`，copy 与 move 目标 `target-exists=true`、move 源 `source-gone=true`、recycle 后 `source-removed=true`——**一次真实的 copy→move→recycle 全链路在本机完成**。
  - 定性过程：一度出现的 `move: error=AccessDenied callbacks=0` 经裸 COM 诊断（`PerformOperations` 真实 hr=`0x00000000`）与源码核对，确认是探针构造缺陷——三个操作共用一个 snapshot，而 `OpPlanBuilder.TryBuild` 要求 `Sources == Target.Selection`，move 源与 copy 快照不一致被拒；已修正为每次操作按自身源集合建自洽快照。产品 `ShellTransport` / COM 本身无缺陷。
  - 阶段 1 全程只在系统 temp 的自建唯一前缀目录内读写并清理，不碰用户文件；stdout 只输出结构化结论字段，无路径、无日志原文（§10 / SECURITY.md）。
- CI：**待实跑**。`real-exe-build` / `real-exe-selftest` / `real-exe-probe-com` / `upload-artifact` 仍无 run 结论；GitHub Actions 的 `windows-latest` 跑在 Session 0、无交互桌面，其 `PROBE-COM.txt` 结论尚未取得。本机交互桌面结论不等于 CI 结论，两者分别登记。
- 证据等级：本机交互桌面为**真机实测（运行态）**，CI 为**待实跑**；H1–H6 / C4 取证仍未执行，`--diagnose` 是规格外诊断装置、不属 Normal 路径，三宿主仍默认关闭、Host 层无启用入口。
- `ReleaseState.IsPublishable() == false`，**M1 / M2 / M3 均不成立，没有发布版本**（诊断通道的跑通不改变发布判据）。

## 偏差登记（未验证 / 不成立）

- 阶段 0/1 探针是诊断装置，不属于 Normal 产品路径；其存在不改变「三宿主默认关闭、CI 不实例化 COM」的事实。
- `--diagnose` 在 §6.4 中语义为通用诊断，本批赋予其 COM 实例化与 transport 试点的具体行为，属规格外诊断扩展，已登记于此。
- 崩溃哨兵、L4 隔离宿主、拖放、七档视图与筛选的完整 UI、会话与书签、单实例后两段、H1–H6 / C4 取证仍未实现或未验证。
- 零写入三段取证（H3）未执行：阶段 1 只在系统 temp 自建目录内写入并清理，不冒充「`data\` 之外零写入已取证」。

## 澄清与作废

- **不作废**：B6 规则层、R2 / R3 / R4 / R5 的默认关闭纪律、§5.2「成熟绑定」偏差（ADR-012）、规格 v1.2 与四档布局。
- **已按实测回填（非作废）**：本机交互桌面已证明 COM 可实例化、一次 copy→move→recycle 全链路可完成，据此修订了上方「证据与结论」段。证据等级仍是「本机真机实测 + CI 待实跑」，不升级为发布结论：三宿主默认关闭的 Normal 路径未变、H1–H6 / C4 未取证、`--diagnose` 不属产品路径。CI Session 0 的结论待 push 后另行回填。
